# Архитектура

## Задача

Агент (Hermes, OpenCode, любой скрипт) и локальная модель с малым окном должны иметь
одну долговременную память: факты о железе, настройках, решениях и ограничениях.
Память живёт на домашнем сервере, доступна по HTTP из LAN, не требует облака и
переживает перезапуски.

Три требования, из которых выросла вся конструкция:

1. **Жёсткий бюджет.** В промпт попадает 400–900 символов, не «сколько нашлось».
   Иначе память съедает окно модели и вредит больше, чем помогает.
2. **Одна точка правды.** Файл SQLite. Бэкап — копия файла, миграция — скрипт на
   старте, отладка — `select`.
3. **Без демонов сверху.** Нет Qdrant, нет Redis, нет очередей. Сервис + эмбеддер.

## Потоки

### 1. Запись

```
POST /remember {text, topic, kind, tags, source, pinned, priority}
  ├── схлопывание пробелов
  ├── _garbage: пусто / только вызовы тулов / слишком коротко / оборванный ход
  │      → {"action":"skipped","reason":"…"}   (в базу не идёт)
  ├── _nkey: sha1 от «букв и цифр» без обёрток «U:», «>», «[ran tool: …]», lower, ё→е
  │      нашли такой ключ? → UPDATE updated_at/tags/pinned/priority
  │                          {"action":"duplicate"}
  ├── _near_dup: кандидаты через FTS по основам слов, Jaccard ≥ 0.9 в том же kind
  │      (только fact/decision/constraint/settings) → склейка
  │                          {"action":"merged"}
  ├── INSERT ... ON CONFLICT(topic,kind,text) DO UPDATE
  │                          {"action":"inserted"} или {"action":"updated"}
  └── вектор: _embed → fact_vec (rowid = fact_id) + опционально Qdrant
```

Вектор пишется **после** коммита и отдельно: недоступный эмбеддер не блокирует
запись, факт остаётся доступен через FTS.

### 2. Поиск

```
GET /recall?q=…&limit=5&budget=400
  ├── FTS: OR по 12 словам запроса, bm25, top limit*3
  │        вклад: fts_w / (60 + rank)
  ├── вектор: bge-m3 → cosine, top limit*2
  │        вклад: vec_w / (60 + rank)      (складывается с FTS-вкладом)
  ├── score = RRF × (0.5 + priority/100)   приоритет усиливает, но не переворачивает
  ├── опционально: реранк top-N (по умолчанию off)
  └── выдача: max_chars → per_topic → dedup → budget
```

### 3. Автоподхват (хук)

```
hook_event → stdin JSON ─► клиент (4 мс) ─► POST /recall_hook
                                             ├── если q < 8 символов: пусто
                                             ├── _recall_run(limit*3, budget*3, max_chars≤500)
                                             ├── пересечение основ слов запроса и факта == 0 → выброс
                                             ├── score < min_score (0.015) → выброс
                                             ├── порядок: score + 0.02 × overlap
                                             └── построчная нарезка: per_line = max_chars // limit
                                            ◄── {"context": "- [тема] факт…", "n": 3}
context ─► в сообщение пользователя (не в system prompt)
```

Важное решение: память вставляется **в user-сообщение**, а не в системный промпт —
иначе каждый ход инвалидирует кеш промпта.

### 4. Наполнение

```
скилы (89 каталогов) ──► skills_index.py ──► чанки 700 симв. ──► topic skill/<имя>, kind skill
история чатов        ──► sessions_index.py ──► окна диалога   ──► topic chat/<YYYY-MM>, kind chat
Nextcloud / inbox    ──► ctxagent :8091   ──► чанки ~1100 симв. ──► topic nc/<путь>, inbox/<файл>
транскрипт ──────────► session_ingest.py  ──► модель-экстрактор ──► 1–10 фактов
```

Индексаторы инкрементальны: хеш файла/сессии в `*.state.json`, при изменении старые
чанки удаляются через `DELETE /forget?id=` и заливаются новые.

## Сервисы вокруг (на этом сервере)

| Порт | Сервис | Роль в памяти |
|---|---|---|
| 8090 | contextd | сама память: запись, поиск, хук |
| 8091 | ctxagent | MCP-обёртка, синк источников, `/ask` с реранком |
| 8081 | llama-embed | `bge-m3-q8.gguf`, эмбеддинги 1024d |
| 8083 | llama-rerank | `bge-reranker-v2-m3`, включается по флагу |
| 8088 | ctxproxy | OpenAI-шлюз, вставляет память в чат-запрос (вне репо) |

## Почему именно так

| Решение | Причина |
|---|---|
| SQLite, не Postgres | один файл, бэкап копированием, 9 тыс. записей — это ничто для SQLite |
| FTS5 + вектор, а не только вектор | запросы с кодами железа (`PF450`, `p104`) ловятся лексикой, а перефраз — вектором |
| sqlite-vec, не Qdrant | +1 демон и +1 сетевой хоп ради 9 тыс. векторов — плохая сделка |
| RRF, не сложение нормализованных скоров | bm25 и cosine несоизмеримы, ранги соизмеримы |
| Приоритет множителем 0.5–1.5 | `constraint` должен всплывать, но не отменять релевантность |
| Хук на сервере | клиент остаётся тонким: тюнинг выдачи не требует обновлять агента |
