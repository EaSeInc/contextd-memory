# HTTP API

Все эндпоинты, кроме `/health`, требуют токен: заголовок `X-Context-Token: <токен>`
или `Authorization: Bearer <токен>`. Если `CONTEXTD_TOKEN` в окружении пустой,
проверка отключается — так удобно в тестах, на сервере так делать нельзя.

Токен задаётся в `/etc/contextd/contextd.env`, база — `CONTEXTD_DB`
(по умолчанию `/srv/contextd/context.db`).

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | состояние, счёт фактов, бэкенды векторов |
| POST | `/remember` | записать факт (с дедупом) |
| POST | `/remember_bulk` | то же пачкой |
| GET | `/recall` | гибридный поиск в бюджете |
| POST | `/recall_hook` | блок памяти, готовый к вставке в промпт |
| GET | `/context` | всегда-включённый блок (pinned) |
| POST | `/pin` | закрепить/открепить запись |
| POST | `/reindex` | пересчитать векторы |
| DELETE | `/forget` | удалить запись или тему |
| POST | `/dedupe` | уборка накопленных дублей и мусора |

## GET /health

```json
{"ok": true, "facts": 9212, "pinned": 3, "vectors": true,
 "qdrant": false, "qdrant_points": null, "sqlite_vec": true,
 "db": "/srv/contextd/context.db"}
```

`qdrant: false` при `sqlite_vec: true` и `vectors: true` — рабочая конфигурация,
а не деградация. `/health` отвечает без токена, чтобы работал мониторинг.

## POST /remember

```bash
curl -s -X POST localhost:8090/remember \
  -H "X-Context-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{"text":"PF450 тянет одну карту ~180 Вт, две нет","topic":"infra/power","kind":"constraint"}'
```

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `text` | str, ≥1 | — | одна мысль, 1–2 предложения |
| `topic` | str | `general` | ключ темы: `print/petg`, `infra/power`, `skill/<имя>` |
| `kind` | str | `fact` | `fact` · `decision` · `constraint` · `settings` · `skill` · `chat` (можно свои) |
| `tags` | str | `""` | пробелы разделяют теги |
| `source` | str | `manual` | кто положил: `manual`, `skills-index`, `chat-index` |
| `pinned` | bool | `false` | попадает в `/context` всегда, priority 100 |
| `priority` | int 1–100 | по `kind` | явно перебивает автоматический |

Ответ всегда `ok: true` плюс исход:

```json
{"ok": true, "id": 9137, "action": "inserted", "priority": 75}
```

| `action` | Что произошло |
|---|---|
| `inserted` | новая запись |
| `updated` | тот же `(topic, kind, text)` — обновлены теги/приоритет/время |
| `duplicate` | тот же текст после нормализации (`U:`, `>`, `[ran tool: …]`, регистр, ё, пробелы) — вернулся id существующей |
| `merged` | смысловой почти-дубль в том же kind (Jaccard основ ≥ 0.9) — записи слиты |
| `skipped` | мусор; причина в `reason`: `пусто`, `только вызовы тулов`, `слишком коротко`, `оборванный ход` |

Вектор пишется после записи в базу. Недоступный эмбеддер не мешает `inserted`:
факт найдётся лексикой, вектор досчитается `/reindex`.

## POST /remember_bulk

```json
{"items": [{"text": "…", "topic": "…", "kind": "skill"}, {"text": "…"}]}
```

Ответ: `{"ok":true,"count":N,"items":[{"id":…,"action":…}, …]}`. Каждый элемент
проходит тот же путь, что и одиночный `/remember`; порядок сохраняется.
Индексаторы шлют этим эндпоинтом по 32 записи, чтобы не платить RTT за чанк.

## GET /recall

Единственный «умный» эндпоинт. Все параметры необязательны.

| Параметр | По умолчанию | Диапазон | Смысл |
|---|---|---|---|
| `q` | `""` | | запрос; пустой — просто свежие записи |
| `limit` | 8 | 1–50 | сколько записей вернуть максимум |
| `budget` | 800 | 100–8000 | бюджет токенов на выдачу (`len/3.2`) |
| `max_chars` | 250 | 60–8000 | обрезка текста в выдаче (база не меняется) |
| `per_topic` | 2 | 1–50 | не больше N записей одной темы |
| `dedup` | true | | выброс почти одинаковых (Jaccard основ ≥ 0.72) |
| `fts_w` | 0.3 | 0–5 | вес лексического канала в RRF |
| `vec_w` | 1.0 | 0–5 | вес векторного канала |
| `recency_w` | 0.0 | 0–2 | буст свежести (выключен) |
| `recency_days` | 14 | 1–365 | полураспад свежести |
| `chat_w` | 1.0 | 0–5 | множитель для `kind=chat` (штраф, если < 1) |
| `rerank` | false | | переставить top-N кросс-энкодером |
| `rerank_n` | 12 | | сколько кандидатов отдать реранку |

Ответ:

```json
{
  "query": "какое сопло для петг",
  "context": "- [print/petg] PETG печатать: сопло 240, стол 80",
  "items": [
    {"id": 9137, "topic": "print/petg", "kind": "settings",
     "text": "PETG печатать: сопло 240, стол 80", "cropped": false,
     "tags": "", "pinned": false, "priority": 65, "score": 0.03211}
  ],
  "tokens_est": 18,
  "budget": 800,
  "dropped": {"dup": 0, "topic": 0, "cands": 14},
  "vectors": true
}
```

`dropped.cands` — сколько кандидатов дошло до сортировки, `dup` и `topic` — сколько
выкинули ограничители. Если нужного факта нет, а `cands` большой — проблема в
фильтрах выдачи или в отборе, а не в «поиск не работает»; диагностика — `docs/retrieval.md`.

## POST /recall_hook

То, что дёргает shell-хук агента. Тело:

```json
{"q": "текст сообщения пользователя", "limit": 4, "budget": 350,
 "min_score": 0.015, "max_chars": 900, "stem_boost": 0.02}
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `q` | `""` | запрос; короче 8 символов — сразу пустой ответ |
| `limit` | 4 | сколько строк памяти максимум |
| `budget` | 350 | внутренний бюджет recall (×3) |
| `min_score` | 0.015 | нижняя отсечка RRF-скора |
| `max_chars` | 900 | общий размер блока, режется построчно |
| `stem_boost` | 0.02 | прибавка за каждое совпадение основ |

```json
{"context": "Память (найдено по запросу, может быть нерелевантно):\n- [print/petg] сопло 240 …",
 "n": 3, "dropped": 1}
```

Пустой `context` — нормальный ответ: хук молчит и ход идёт без памяти. Причина
`reason: short` / `no-stems` говорит, на каком шаге отвалилось.

## GET /context

Всегда-включённый блок: `pinned=1` плюс свежее, уложенное в `budget` (по умолчанию
800). Используется, когда нужен «cheat sheet» в начале разговора, а не под запрос.

Параметры: `budget` (100–8000), `pinned_only` (bool). Ответ — `{"context": "- …", "items":[…], "tokens_est": N}`.

## POST /pin

`?id=42&pinned=true` — ставит `pinned` и `priority=100`; `pinned=false` снимает
закрепление (приоритет остаётся, если не передан явно).

## POST /reindex

`?limit=100000` — считает эмбеддинги для фактов, у которых их нет, начиная с
наименьшего id. Долгий вызов на 9 тыс. записей: гонять в фоне и смотреть `/health`.
Ответ: `{"ok":true,"indexed":N,"total":M,"backend":"sqlite-vec"}`.

## DELETE /forget

`?id=42` — одна запись, `?topic=cad` — вся тема. Возвращает
`{"ok": true, "deleted": N}`. Факт, ключ и вектор удаляются вместе.

## POST /dedupe

`?apply=false` — только посчитать, `apply=true` — удалить. `garbage=true`
дополнительно сносит записи из вызовов тулов и оборванных ходов. `limit` —
сколько групп просматривать (по умолчанию 20 000).

```json
{"ok": true, "dry_run": true, "groups": 0, "would_delete": 0, "sample": []}
```

Группировка по нормализованному ключу, из группы остаётся самая длинная запись
(при равенстве — самая старая). Перед `apply=true` — бэкап базы: операция
необратимая и, как всякая массовая уборка, имеет право ошибиться.
